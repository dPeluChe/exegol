## 2026-09-24: resume Claude sessions after a reboot (branch `fix/resume-after-crash`)

Reported from 0.5.0: the Mac shut down with 4 agents running (app got SIGTERM at 14:33, booted
16:45). Recovery marked them crashed as designed, but none could resume: `claude_session_id` and
`resume_command` were empty on all four. The id came from a "Session ID:" banner Claude Code no
longer prints, and the resume command only appears on a clean exit.

- [x] `notify.sh` reads the hook payload Claude Code pipes on stdin (drained whole, parsed from the
  first 4KB) and adds `sessionId` to the event file
- [x] `dispatchAgentFileEvent` stores it as `claude_session_id` (claude-code only, id-shaped only,
  latest wins since /clear starts a new session) before the OSC short-circuit; the existing
  resume path already runs `claude --resume <id>`
- [ ] Not covered: Devin and other CLIs without hooks still resume only from a clean exit's output

## 2026-09-24: no automatic token-limit handoff (branch `fix/no-token-limit-handoff`)

Reported from the installed 0.5.0: a resumed Devin session showed "Token limit approaching" 10s
after spawn; each "Continue with new agent" click spawned a successor that did the same, three
exited 1, and "Needs attention" on them opened nothing.

- [x] Removed the whole handoff chain: substring detection (Rust `check_token_limit` and the JS
  mirror matched any line with "context window" or "token limit", and the injected handoff prompt
  itself ended with "context window was exhausted"), handoff creation, the live banner, the
  stopped-agent "Continue" button, `agents.getHandoff`/`continueWithHandoff`, `agent:handoff-ready`.
  CLIs (Claude Code, Devin, Codex) compact their own context; replacing the session was never
  wanted. The `handoffs` table stays (migrations are append-only). A future context warning has to
  come from a provider signal (hook/OSC), not scraped text
- [x] `jumpToAgent` opens the agent in a new tab when no pane shows it (successors were spawned
  without a pane), instead of doing nothing; it never replaces an existing pane
- [x] Simplify pass: the parallel-run comparator's "Open" goes through `jumpToAgent` too
  (`focusAgentPane` overwrote the active tab's first pane and never switched project); dead
  `token_limit` event type and stale ARCHITECTURE entries removed
