- [x] `system/process-table.ts`: `readProcessTable` moved out of `shell-clis.ts` (re-exported), with a Windows reader (`Get-CimInstance Win32_Process` as JSON, `parseWin32Processes`) used by pane kill, idle suspend and the sidecar check before Restart terminals. - [x] `lib/win-launch.ts`: a `.cmd`/`.bat` IDE launcher (and the custom IDE path on Windows) runs through `cmd.exe /d /s /c` with cross-spawn's quoting; `windowsHide` on that and the detached sidecar

## 2026-10-20: AppImage launch form, Wayland hotkey, lsof and playerctl (branch `fix/linux-appimage-wayland`)

An AppImage runs from a FUSE mount (`/tmp/.mount_*`) that its runtime removes once the app quits. The detached PTY sidecar, the MCP shim in the agents' configs and the claim guard in the hook settings were all `process.execPath` plus a script in that mount, so they broke with it, and app-relocation rewrote every file on each launch because the mount moved every time.

- [x] `system/node-launch.ts` (pure, tested): `nodeLaunch(script)` is `execPath script` everywhere but an AppImage, where it is `$APPIMAGE -e <code>`: the file mounts itself again and the code finds the script beside the new mount's binary, run through `module.runMain` (the guard runs only as the main module). `nodeShellCommand` for the hook. Used by the sidecar spawn, every MCP config (per-agent, project files, the codex block) and the guard. macOS, the .deb and the .rpm keep the same commands
- [x] `app-location.ts`: an AppImage's root is its `.AppImage` file (`appRoot`); `app-location.json` records `appImage`; no relocation between an AppImage and an installed copy, nor from an older record naming a mount; `swapRoot` also moves a path equal to the root (the file), not only under it
- [x] Wayland: `enableShortcutsPortal` adds `GlobalShortcutsPortal` to `enable-features` (merged) on Linux before ready; `registerGlobalHotkey` says on Wayland that a failure is a missing or refusing portal and that a success is a request the desktop may confirm
- [x] `ports.ts`: `lsofStdout` throws when lsof did not run (missing, timed out), so `listTcpListeners` rejects and idle auto-suspend skips with "no port info" instead of finding no listeners; dev servers and project ports keep showing none. `readProcCwds` reads `/proc/<pid>/cwd` on Linux before lsof
- [x] Doctor: `playerctl` warning on Linux beside the `lsof` one
- No `SIDECAR_VERSION` bump: the sidecar's own code is unchanged, only how main launches it
- Not tested on Linux: everything above needs the real AppImage and a Wayland session (steps in TASK_TODO). Known limits: `APPIMAGE_EXTRACT_AND_RUN` extracts to one shared folder that the first instance to exit deletes; sessions started before this build still run from the old mount

- [x] Why: user log (packaged, 27 live sessions) `done 27 in 32888ms`, one session every 1-2 s

  xterm parse (~135 ms). Cause: `lib/ndjson` appends each socket chunk to one string and its
  `indexOf` flattens that string every time; macOS delivers unix socket data in 8 KB reads, so a
  12 MB snapshot frame is ~1,400 chunks and a quadratic copy (1.2 s for an 11 MB frame in a
  micro bench, 0.18 s in 64 KB chunks). Main-thread CPU, so the 3 workers serialized
- [x] Fix: `terminal/frame-buffer.ts` (now `lib/frame-reader.ts`), used by `pty-sidecar-client`: scans each chunk once
  for the newline and joins a frame once. `lib/ndjson` is bundled by the sidecar, so it stays
  (no SIDECAR_VERSION bump); its fix is noted in TASK_TODO T185.8
- [x] After: 4.6 s total for the same 27 (12x); per 8 MB ring fetch ~150 ms + parse ~135 ms, per
  1 MB shell ~20 ms parse; longest main-thread block ~250 ms. Lazy or chunked parsing was not
  needed: the parse is ~4 s of the remaining total and the pool keeps the panes' order
- [x] `[Reattach] OK` lines now carry `fetch Nms, N KB, parse Nms` per session
- [x] Garbled first frame: the ring is parsed at the stored grid and a pane's size is applied
  after it. A resize that arrived mid-replay resized the model while the rest of the ring was
  still being parsed; it is now held in `pendingSizes` until the parse ends. When the pane's size
